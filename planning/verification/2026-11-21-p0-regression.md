## 边界与下一关

- 授权验证分两段：SQLite 的旧名单不会变成新授权，客户端对有效写动作生成专属键。缺失或无效动作的候选键仍可能是工具整名；**这里没有验证最终允许/拒绝决策**。下一批应以无副作用的桩验证完整审批链，不实际执行受保护工具。
- 快照验证的是持久层字节不被二次写入覆盖；回滚覆盖生产选择、截断和清理接口，不是完整 UI / IPC 或 MCP 提示词渲染测试。工作区重关联、孤儿清理、插件包校验和更多历史样本仍待补齐。
- 此批没有在 Unix 执行，没有跑全工作区 Cargo 测试、打包或真实数据库升级；没有启用 GitHub Actions、配置分支保护、同步标签或发布。上述项不能用 Windows 本机的绿灯代替。
- 交接时原工作区仍在 `main` 的 `5f8cde66`，原来两份未提交规划的 SHA-256 与复制前一致。新测试只在隔离工作树；下一阶段的放行条件见[详细战略](../strategy.md)。
